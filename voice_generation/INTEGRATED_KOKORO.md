# Kokoro in the private practice website

The combined demo branch `parth/demo-ready` includes the team practice site,
profile improvements and the isolated Kokoro connection. See
[the combined guide](../docs/COMBINED_DEMO.md) for the current demo entry point.

## Run

From the main `accent_coach` folder in VS Code:

```powershell
.\.venv\Scripts\python.exe app_2.py
```

Open http://127.0.0.1:7861/. Create a local account or sign in. Select **My own
sentence** or **Free speech**, upload/record your original WAV, review or enter
the words, and confirm the transcript. Press **Hear a synthetic example**.
The private example is now generated by Kokoro `af_heart` by default.
Text remains limited to 12 words / 200 characters; recordings remain at most
five seconds. Generated audio is a synthetic example, not the learner's voice.

The first example loads the model. Later examples reuse the same process. After
an edit, confirm the updated words and generate again. Failed generation offers
a retry and does not erase completed pronunciation feedback.

## Separate environments

The website uses root `.venv`; Kokoro uses `voice_generation/.venv` and its local
`models/kokoro` weights. No Kokoro/Transformers imports occur in the main app's
generation adapter. The main site's existing requirements and account/scoring
dependency pins remain separate from Kokoro's pins.

One-time setup for another checkout:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-accounts.txt -r requirements-scoring.txt
# Follow KOKORO_RUNBOOK.md to set up the isolated generation environment/weights.
```

Optional server configuration in the same PowerShell terminal before launch:

```powershell
# Use a different existing generation environment:
$env:ACCENT_COACH_KOKORO_PYTHON = 'C:/path/to/generation-env/Scripts/python.exe'
# Explicitly choose the previous desktop voice instead of Kokoro:
$env:ACCENT_COACH_GENERATION_BACKEND = 'windows'
# Return to the Kokoro default:
$env:ACCENT_COACH_GENERATION_BACKEND = 'kokoro'
```

Missing Kokoro setup returns a retryable error; it does not silently substitute
Windows TTS. Model/voice downloads never happen during generation.

## Private transport and lifecycle

`IsolatedKokoro` in `bridge.py` starts the separate interpreter only on the first
generation request. `stdio_worker.py` loads/caches the model and serves serialized
JSON-lines requests. Inputs come from the authorized session snapshot. Its working
directory is server-created private job storage, never a browser-supplied path.
The worker transfers bounded WAV bytes back through a private pipe; no public
audio server or unrestricted filesystem route is added.

The main app validates opaque synthetic IDs, WAV format and output size, then
publishes bytes through the existing SQLite owner/revision/job checks. Playback
continues through authenticated asset routes. The worker is terminated on a
120-second response timeout or transport failure and closed at app shutdown.
Private temporary outputs are removed by the existing job-directory lifecycle.
Generation stage timings retain model-load, synthesis and request measurements.

## Verification and limits

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_kokoro_bridge.py -v
.\.venv\Scripts\python.exe tools/check_private_kokoro.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
```

Verification completed on this laptop: 162 full-suite tests ran, with 161 passing and one existing Windows symlink skip. All seven bridge tests passed; both dependency checks passed. The real private Kokoro flow passed 29 checks.

The private Kokoro check uses temporary accounts/database and synthetic test input.
It performs real Kokoro generation, login/HTTP/SQLite/private playback, second-user
access denial and a missing-runtime failure. It verifies cold then warm model
reuse and preservation of prior analysis on failure. **Recognition and assessment
are controlled fixtures in this check**, not real speech-model/accuracy evidence.
Results are saved under ignored `runs/kokoro_private_integration_smoke.json`.

Real observed processing times in this check were 46.860 seconds cold and 1.063
seconds warm for **I think so**. Startup conditions and OS load are uncontrolled;
these are measurements from this run, not latency promises.

On this laptop, transcript confirmation uses a copy of the existing complete MFA
dictionary under ignored `models/mfa/`, selected through ignored
`phoneme_scoring/settings.local.json`. No personal path is committed. Installing
Python dependencies does not install Whisper/phoneme checkpoints or the MFA
runtime/acoustic model. Configure those using the team's model setup instructions
before expecting real recognition and pronunciation analysis; manual transcript
entry can still be confirmed for synthetic generation.

This work does not implement voice-preserving conversion, public hosting, or
validated pronunciation grades. Existing private account storage is unchanged.
